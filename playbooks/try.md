# 劇本：先試玩（在這台電腦上開一個虛構班級的網站，不用任何帳號）

老師會說：「先給我看看長什麼樣」「先試玩」「還不想裝，先玩玩看」「用假的資料試一下」。
新裝開始前（`AGENTS.md` 步驟 0 之前）也可以主動問一句：「要不要先花 5 分鐘試玩一個假的班級網站，再決定要不要裝？」

腳本：`scripts/try_emulator.py`。它在這台電腦上開 Google 官方的「模擬器」（Firebase Emulator）：網站、登入、資料庫
都是假的、只在這台電腦上跑，**不用 Google 帳號、不用 Firebase 專案、不碰任何雲端**。裡面是虛構的一班
（學生 A～Y、家長與同仁都是 `@example.com` 的假信箱、照片是程式畫的色塊圖），內容跟示範站同一份。
網站本身、登入後誰看得到什麼的規定，都是正式網站會用的那一份。

試玩跟安裝互不影響：試完收掉，這個資料夾就回到原樣（只多了下載的模擬器工具），再照 `AGENTS.md` 步驟 0 開始裝。

## 1. 代理要問什麼（一次一題）

1. 「試玩需要兩個免費的官方工具：Node.js（之後正式安裝本來就要裝）和 Java（只有試玩要用）。我先看看你的電腦有沒有，可以嗎？」
   （這一題問完直接跑第 3 段第 1 點，不用等他回答工具的事。）
2. 缺工具時：「還少〈名稱〉，要到官方網站自己裝，我告訴你去哪裡按哪個按鈕。要現在裝，還是先不試玩、直接開始正式安裝？」
3. 第一次試玩：「我要先下載試玩用的模擬器工具，大約 400 MB，全部放在這個資料夾裡、不會裝到電腦的其他地方；
   不要了把那個資料夾丟垃圾桶就乾淨了。可以下載嗎？」
4. 開好之後：「網站開在你的瀏覽器裡了。按『用 Google 帳號登入』會跳出一個假的登入頁，點『示範導師』就是你的樣子；
   想看家長那邊，登出再點『學生 A 家長（母）』。看完跟我說一聲，我把它收掉。」

## 2. 老師去哪裡拿

- **Node.js**：跟 `AGENTS.md` 步驟 1-3 一樣（<https://nodejs.org/en/download> → 標著 LTS 的版本 → Mac「macOS Installer (.pkg)」、
  Windows「Windows Installer (.msi)」→ 一路下一步）。
- **Java**（21 以上；只有試玩要用）：<https://adoptium.net/> → 首頁的下載按鈕（Temurin，選 LTS）→ Mac 下載 `.pkg`、
  Windows 下載 `.msi` → 打開，一路下一步（每一頁的預設值就好；腳本會到常見的安裝位置找 Java）。
  Mac 用 Homebrew 裝過 `openjdk` 的也可以，腳本找得到。
- 裝完任何一個：關掉代理和所有終端機視窗，重開、回到這個資料夾、再啟動代理，跟它說「繼續試玩」（`AGENTS.md` 平台對照最後一列）。
- 其他什麼都不用準備：不用 Google 帳號、不用信用卡、不用手機。

## 3. 代理要做什麼

1. 檢查（唯讀，直接跑）：Mac `python3 scripts/try_emulator.py --check`；Windows `py -3 scripts/try_emulator.py --check`。
   - Java 或 Node.js 打 ✗ → 把它印的官方連結給老師（第 2 段），**你不跑任何安裝指令**（`AGENTS.md` 鐵則 10）。
   - 「模擬器工具：還沒下載」→ 問第 1 段第 3 題，他點頭才加 `--download`。這是**唯一**一個你可以替他下載東西的地方：
     版本照 `tests/rules/package-lock.json` 釘死，只寫進這個資料夾的 `tests/rules/node_modules/`，不用 `npm install -g`。
2. 開試玩環境。它會一直跑到收掉為止，所以：
   - 你的執行工具能「在背景跑」（例如 Claude Code）→ 在背景跑 `python3 scripts/try_emulator.py`（第一次加 `--download`），
     等輸出出現「✓ 試玩環境開好了」。第一次要下載 Firestore 模擬器本體（約 140 MB），可能要幾分鐘。
   - 不能在背景跑 → 請老師在**他自己的終端機視窗**貼那一行（Windows 用 `py -3`），看到「✓ 試玩環境開好了」跟你說；
     之後你用 `python3 scripts/try_emulator.py --status` 看網址（唯讀）。
3. 開好會自動打開瀏覽器（沒打開就把它印的網址 `http://127.0.0.1:8765/` 給老師）。照第 1 段第 4 題陪他看：
   首頁、班級紀事、相簿、「我的孩子」、導師專用；換成家長帳號看看哪些東西不見了。
4. 想試「我說一句話、你幫我發」：在試玩環境裡，所有腳本都加 `--root try --emulator`，就寫進這個假網站、不碰雲端。例如：
   - 發一篇紀事：照 `playbooks/class-post.md` 寫 `try/data/class-posts/<日期>-hello.md`，然後
     `python3 scripts/publish_post.py <日期>-hello --root try --emulator`（預覽）→ 他點頭 → 同一行加 `--publish`。
   - 名單：`python3 scripts/access_sync.py --root try --emulator`（名單檔在 `try/data/`，是虛構的，你可以打開）。
   - 腳本印的「再跑：…」會自己帶著 `--root "try" --emulator`，照抄就好。**少了 `--emulator` 會去連雲端；少了 `--root try`
     會去讀這個資料夾真正的設定**——試玩時兩個都一定要帶。
   - 試玩環境沒有雲端硬碟，備份、課程歸檔這幾支在這裡試不了。
5. 收掉：在跑它的那個視窗按 `Ctrl-C`（你在背景跑的就停掉那個背景工作）。模擬器、本機網站、`try/` 資料夾一起清掉，
   試玩時發的東西也都不見（本來就是假的）。
6. 試完：問他「要開始正式安裝了嗎？」要的話照 `AGENTS.md` 步驟 0。試玩不寫 `setup/progress.json`。

## 4. 怎麼驗證＋失敗怎麼辦

- 成功：瀏覽器開得到 `http://127.0.0.1:8765/`，用「示範導師」登入後首頁有紀事、相簿有照片；收掉後 `try/` 不見了、
  `--status` 說「沒有開著」。
- exit 2（什麼都沒開）：
  - 缺 Java／Node.js → 第 2 段；裝完要重開終端機與代理。
  - 「要先下載試玩用的模擬器工具」→ 第 1 段第 3 題。
  - 「埠 8080、9099 已經有程式在用」→ 多半是試玩環境已經開著：`--status` 看網址。上一次沒收乾淨的話，請老師關掉
    那個終端機視窗（或重開電腦）再試。
  - 「try/ 不是試玩程式建的，不動它」→ 請老師看一下那個資料夾是什麼，不要了自己移到垃圾桶。
- exit 1：
  - 「模擬器沒有起來」＋最後幾行紀錄 → 多半是 Java 版本太舊（要 21 以上）、第一次下載時網路斷了，或防毒軟體擋了。
    修好再跑一次，重跑是安全的（`try/` 每次都重建）。
  - 下載模擬器工具失敗 → 網路問題：確認連得上網再跑一次 `--download`。
- 網頁說登入元件載不下來：網站要從 Google 的網站（www.gstatic.com）載登入元件，這台電腦要能上網；
  公司或學校的網路擋住的話，換一個網路（例如手機熱點）再開。
- 登入頁跳不出來：瀏覽器擋了彈出視窗 → 允許這個網址的彈出視窗，再按一次。
- 試玩裡看到的東西跟真的網站一樣，只差在：真的 Google 登入畫面、LINE 裡開網址、手機照片、每天 5 封的登入信、
  真的部署——這些要正式安裝後（`AGENTS.md` 步驟 8）才驗得到。
