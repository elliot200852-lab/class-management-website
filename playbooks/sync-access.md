# 劇本：同步家長名單（誰進得了網站）

老師會說：「同步家長名單」「加一位家長」「某某家長換信箱了」「3 號轉走了」「讓某位同仁看得到 5 號的部落格」。

腳本：`scripts/access_sync.py`。它讀 `data/roster.csv`、`data/contacts.csv`、`data/parent-roles.yaml`、`config/class.json`，
寫進網站的名單（班網讀者、私密讀者、家長對座號、導師名冊、站台資訊）。**預設只預覽**，`--apply` 才寫。

## 1. 代理要問什麼（一次一題）

1. 「這次名單有什麼變動？」（新家長、換信箱、轉出、轉入、同仁、私密讀者）——只是要知道他改了哪裡，不用他念出信箱。
2. 如果他還沒改檔案：「請你用 Excel（或 Numbers）打開 `data/contacts.csv`，照第一列的欄位改好後存檔，改好跟我說。」
3. 如果有轉入／轉出、或家長新開／不再需要帳號：「`data/parent-roles.yaml` 也要一起改，我可以幫你改這個檔嗎？」
   （這個檔沒有姓名與信箱，你可以打開、照他說的改。）

## 2. 老師去哪裡拿

- 家長的 Google 信箱：家長自己提供（LINE、紙本調查表）。**建議用 Google 帳號**（Gmail 或學校的 Google 帳號）：
  「我的孩子」只接受 Google 登入；沒有 Google 帳號的家長也能用信箱連結登入班網，但免費方案全網站每天只能寄 5 封登入信。
- `contacts.csv` 的欄位：`座號,關係,姓名,Email,私密讀者,暫停,備註`
  - 一列一個「人 × 座號」。家長：座號必填、關係寫「母」「父」「祖母」……（要跟 `parent-roles.yaml` 寫的一模一樣）。
  - 一位家長有兩個孩子在同班：寫兩列（兩個座號），信箱一樣。
  - 同仁：關係填「同仁」；座號空著＝只看班網，填座號＝也能讀那個座號的部落格（一列一個座號，最多 3 個）。
  - 私密讀者：填「是」＝看得到私密紀事。暫停：填「是」＝暫時拿掉座號權限（資料保留）。
  - 存檔時選「CSV UTF-8」最好；Excel 預設的 Big5 也讀得懂。
- `roster.csv` 的欄位：`座號,姓名,稱呼,備註`（稱呼＝家長在網站上看到的孩子稱呼，只放名、不放姓，最多 10 字）。
- 導師自己**不要**寫進 `contacts.csv`：程式會自動把 `config/class.json` 的導師信箱加進兩份名單。

## 3. 代理要做什麼

1. 先預覽（唯讀，直接跑）：
   ```
   python3 scripts/access_sync.py
   ```
2. 把預覽的重點用白話講給老師聽：要新增誰、更新誰、移除誰（輸出只有座號、稱謂、遮住的信箱）。
   有「提醒」就一定要講（例如「座號 15 的『母』有 2 個不同的信箱：確認沒有打錯座號」——座號打錯會讓家長看到別人孩子的部落格）。
3. 老師確認後，說「我接下來要把名單寫進網站，寫完這幾位家長就能登入（或失去權限）」，他點頭才跑：
   ```
   python3 scripts/access_sync.py --apply
   ```
4. 學生轉出、學年換班這種一次移除很多人的情況：腳本會停下來說「會讓 N 個人失去權限，超過上限 3」。
   先跟老師確認這 N 個人真的都要移除，他同意了才照腳本印的指令加 `--max-deletes N`。**不要自己主動加大。**
   學年結束請走 `playbooks/year-end.md`，不要用這支清空。
5. 轉出的學生：名單同步只撤權限。部落格、留言等資料的刪除走資料退場（`playbooks/data-exit.md`）。
6. 改了 `config/class.json` 的導師稱呼、校名、人數、行事曆網址，也是跑這支（它會更新站台資訊）。

## 4. 怎麼驗證＋失敗怎麼辦

- 成功的輸出最後一行是「✓ 已寫入 N 筆……讀回比對一致」。再跑一次預覽應該是「已經跟本機一致，沒有要改的」。
- 唯讀檢查名單的包含關係：`python3 scripts/access_sync.py --check`（exit 0＝導師在兩份名單、私密讀者與座號對應都在班網名單裡）。
- 請老師找一位家長實際登入試試（用手機、用那位家長的 Google 帳號）。
- exit 2「安全閘擋下來了，一筆都沒有寫」：
  - 「低於下限」：`contacts.csv` 可能被截斷或存壞了。請老師打開檢查；真的有很多家長還沒給信箱，就把 `parent-roles.yaml`
    裡那些還沒有帳號的稱謂拿掉（或改成 `[]`）。
  - 「表頭少了這幾欄」：第一列被改掉了，照訊息裡的欄位名稱改回來。
  - 「第 N 列：Email 格式不對」：請老師看第 N 列的信箱（訊息不會印出信箱本身）。
  - 「學年封存的安全閘擋下來了」（預覽開頭也會說「學年已封存：名單改好了嗎？」）：學年結束做過 `data_exit.py year-end`，
    三個名單檔可能還是上一屆的。問老師「名單改成新學年的了嗎？」他確認是新名單、看過預覽，才加 `--apply --new-roster`；
    還沒改就照 `playbooks/year-end.md` 第 3 段先改。
- exit 1 且訊息提到 gcloud、權限、網路：照訊息的「→」處理（多半是 `gcloud auth login` 用開專案的那個帳號登入），修好再跑同一個指令——重跑是安全的。
