# 劇本：每日一詩

老師會說：「幫我選下個月的詩」「放一首詩上去」「這首換掉」「十月的詩拿掉」。

腳本：`scripts/publish_poems.py`。一首一檔：`data/poems/<日期>.md`（寫法見 `data/poems/README.md`），一個月一份放上網站，
名單上的家長與同仁登入後在「每日一詩」看得到（一天揭曉一首）。**兩段式**：預覽 → 老師說好才 `--publish`。

**版權由老師負責。** 這個網站只放**老師確認過可以公開使用**的文本：
公版作品（作者過世很久、確定已進入公共領域）、老師或孩子自己寫的、已經取得授權的。你（代理）一定要守這三條：

1. **不准憑記憶打出有著作權疑慮的現代作品全文**（包括歌詞）。就算只給家長看、就算是「教育用途」，也不行。
2. **不准替老師填 `rights`**（「能不能公開使用」那一欄）。草稿一律留白，老師逐首確認後自己說、你才寫上他說的話。
3. 公版的古典作品也可能記錯字：草稿裡的正文一律註明「請對照你手邊的版本」，請他對過一次。

## 1. 代理要問什麼（一次一題）

1. 「哪一個月？每天一首，還是只有上課日？」
2. 「想要什麼樣的詩？」（季節、節氣、主題、跟這個月的課程有沒有關係、適合幾年級。）
3. 「詩從哪裡來？你手邊有想用的（課本、詩集、自己寫的），還是要我先列一份公版作品的候選清單給你挑？」
4. （草稿做好之後，逐首）「這一首可以公開放在網站上嗎？是公版、你自己寫的，還是有取得授權？」

## 2. 老師去哪裡拿

- 他自己的詩集、課本、自己寫的詩；孩子寫的詩（作者欄寫「本班學生」之類，不寫全名）。
- 要確認一首詩是不是公版：看作者的卒年與出版資訊；不確定的，**就當作不能用**。

## 3. 代理要做什麼（「幫我選下個月的詩」）

1. 列候選清單給他挑（只列詩名、作者、為什麼適合，**不附全文**）；有著作權疑慮的現代作品不要列。
2. 他挑好之後，每一首建一個 `data/poems/<日期>.md`：檔頭 `date`、`title`、`author`、`source`（出處），**`rights` 留空**；
   正文照他提供的版本逐字抄（他沒提供、只有公版古典作品，你寫下來並在對話裡提醒他對照）；可以附一小段 `## 導讀`（你寫的導讀要讓他看過）。
3. 預覽（唯讀，直接跑）：`python3 scripts/publish_poems.py <YYYY-MM> --open`。會列出「還不能上線：這幾首的 rights 是空白的」。
4. 請他逐首看預覽檔（字、作者、出處），並逐首回答第 1 段第 4 題；他說一首，你把他的原話寫進那一首的 `rights:`（例如「公版」）。
   他說不確定或不能用的，就把那一首拿掉（或換成他自己寫的）。
5. 全部都有 `rights` 了，再預覽一次；他說好：「我接下來把這個月的詩放上網站，家長登入後每天會看到一首」，他點頭才跑
   `python3 scripts/publish_poems.py <YYYY-MM> --publish`（這個月已經上過、又改了，要他同意才加 `--update`）。
6. 整個月拿掉：`python3 scripts/publish_poems.py --remove <YYYY-MM>`，他點頭才加 `--publish`（本機的 md 不動）。

## 4. 怎麼驗證＋失敗怎麼辦

- 成功：「✓ 已上線……讀回比對一致」。請他打開「每日一詩」：今天那一首在最上面（今天沒有就是這個月今天以前的最後一首），
  下面列出這個月的每一首；還沒到的日子家長看不到，導師看得到並標「還沒到」。
- exit 2：
  - 「這幾首還沒確認能不能公開使用」→ 回到第 3 段第 4 步，**不要自己填**。
  - 「某天有兩首詩」「日期不在這個月」→ 改檔頭的 `date`。
  - 「正文要 1–2000 字」「導讀要 0–1000 字」→ 太長了，問他怎麼刪。
  - 「網站上的 pages/poems-… 不是每日一詩」→ `data/pages/` 裡有人用了 `poems-` 開頭的頁面代號：停下來跟他說，不要覆蓋。
- exit 1：照「→」處理後重跑同一個指令。
- 不想在導覽列看到「每日一詩」：`config/class.json` 的 `pages` 加 `"poem": false`，重跑 `build_config.py` 再部署（`playbooks/deploy.md`）。
