# 劇本：還原（把備份拉回來）

老師會說：「那篇紀事不見了」「相簿被刪了，救回來」「網站資料壞了」「換電腦了，資料要搬回來」「硬碟壞了」。

腳本：`scripts/backup.py restore firestore`（網站資料庫）、`scripts/backup.py restore records`（這台電腦的 `data/`）、
`scripts/backup.py list`（有哪些備份，唯讀）。

**還原不會刪任何東西**：只把「現在不見的」補回去、「內容被改掉的」改回備份那時的樣子。備份之後才有的留言、文章都會留著。
真的寫之前，程式會先自動做一份「還原前」快照，還原錯了可以再還原回來。

## 1. 代理要問什麼（一次一題）

1. 「是網站上的東西不見了，還是這台電腦裡的檔案不見了？」
2. 網站上的：「是哪一篇（或哪一本相簿）？大概什麼時候還在？」——要知道要用哪一天的備份、只還原哪一篇。
3. 換電腦／硬碟壞了：「新電腦的雲端硬碟裝好、登入了嗎？」（還原要從雲端硬碟拿備份）

## 2. 老師去哪裡拿

- 不用拿任何東西。備份在老師自己的雲端硬碟（`05_全站備份/`、`01_機密（只有導師）/紀錄備份/`），程式自己找。
- 換電腦：先照 `AGENTS.md` 把這個資料夾與 `config/class.json` 裝好，再照 `playbooks/backup.md` 第一次設定接上**同一個**雲端硬碟
  （`drive_init.py --pick …` 選到有「<班名> 班級網站」的那一個；已經有的資料夾不會被動到）。

## 3. 代理要做什麼

網站上的某一篇不見了：

1. `python3 scripts/backup.py list` 看有哪些快照（代號＝日期時間，例如 `20261001-183000`）。挑一份「那篇還在」的時間之後的。
2. 預覽（只讀，直接跑）：
   `python3 scripts/backup.py restore firestore --snapshot 20261001-183000 --only posts/2026-09-30-autumn-walk`
   （`--only` 後面是那一篇的位置：紀事 `posts/<代號>`、相簿 `albums/<代號>`、私密紀事 `private_posts/<代號>`、
   某位孩子的部落格 `student_blogs/<座號>`。代號就是母本的檔名，不含 `.md`。）
3. 把預覽講給老師聽：「會補回 N 份、改回 M 份，其他都不動」。點頭後同一個指令加 `--apply`。

整個網站要還原（資料庫壞了、換新的 Firebase 專案）：

1. 先預覽 `python3 scripts/backup.py restore firestore --snapshot latest`。
2. 換了新專案的話會停下來說「這份快照是別的專案的」：確認真的是要搬家，再加 `--to-other-project`。
3. 老師點頭後加 `--apply`。

這台電腦的 `data/` 不見了（換電腦、誤刪）：

1. 預覽 `python3 scripts/backup.py restore records`（用最新一份；指定某一份用 `--zip records-20261001-183000.zip`）。
2. 已經存在的檔**不會被蓋掉**。老師確定要用備份蓋掉現在的版本，才加 `--overwrite`（先講清楚「你這幾天改的會不見」）。
3. 老師點頭後加 `--apply`。照片與影片會從雲端硬碟的鏡像補回來（已經有的不動）。

## 4. 怎麼驗證＋失敗怎麼辦

- 網站：成功會說「讀回逐欄比對一致」。請老師重新整理網站看那一篇。
- 還原錯了：訊息最後有一行「要反悔」的預覽指令（用還原前快照再還原一次），照著跑、講給老師聽，他點頭再加 `--apply`。
  注意：還原從來不刪文件，所以這次還原**新建**的文件（快照裡有、還原前沒有的），反悔也拿不掉——訊息會說有幾份；
  要收回就照那一種內容的劇本另外下架（`visible: false`）或刪除。
- `data/`：成功後跑 `python3 scripts/status.py`。
- 「找不到快照」：跑 `backup.py list` 看代號有沒有打錯；新電腦上只有雲端硬碟裡的快照，也找得到。
- 「照片池少了 N 份照片」：雲端硬碟可能還沒同步下來。請老師確認雲端硬碟圖示顯示「已是最新狀態」後再試。
- exit 1 跟 gcloud、網路、額度有關：照 `playbooks/backup.md` 第 4 段處理，修好重跑（重跑是安全的）。
